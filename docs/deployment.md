# Deployment Documentation — DSIMS

## 1. Overview

DSIMS is deployed as a production-grade full-stack application on Microsoft Azure with separate hosting for the frontend and backend, and MongoDB Atlas for the database. This separation provides independent scaling, deployment, and monitoring for each layer.

## 4. Frontend Deployment (Azure Static Web Apps)

### 4.1 Service Details

- Service: Azure Static Web Apps
- Tier: Free
- Region: Global CDN with edge locations worldwide
- SSL: Automatic HTTPS with managed certificate
- Custom domain: Not configured (uses default azurestaticapps.net subdomain)

### 4.2 Build Configuration

- App location: `/frontend`
- Output location: `dist`
- Build command: `npm run build`
- Node version: 18 or higher
- Build framework: Vite

### 4.3 Environment Variables

Configured through the Azure Portal Configuration section:

- `VITE_API_URL` — Points to the Azure Web Apps backend URL

### 4.4 Deployment Process

1. Code is pushed to the main branch on GitHub
2. GitHub Actions workflow (auto-generated by Azure) triggers
3. Workflow installs dependencies with `npm install`
4. Workflow builds the React app with `npm run build`
5. Built static files are uploaded to Azure CDN
6. Global CDN propagates changes to all edge locations
7. Users receive the new version from their nearest edge

### 4.5 Routing Configuration

A `staticwebapp.config.json` file handles SPA fallback routing so React Router works correctly for direct URL access to any route.

## 5. Backend Deployment (Azure Web Apps)

### 5.1 Service Details

- Service: Azure Web Apps (App Service)
- Runtime: Node.js
- Region: Southeast Asia (Singapore)
- Plan: Free or Basic tier
- SSL: Automatic HTTPS with managed certificate
- HTTP/2 enabled

### 5.2 Environment Variables

Configured through Azure Portal → App Service → Configuration → Application Settings:

- `PORT` — Auto-provided by Azure
- `MONGO_URI` — MongoDB Atlas SRV connection string
- `JWT_SECRET` — Secret key for JWT signing
- `FRONTEND_URL` — Points to Azure Static Web Apps URL (for CORS)
- `BACKEND_URL` — Own URL for generating email verification links
- `NODE_ENV` — Set to `production`

### 5.3 Deployment Process

1. Code is pushed to the main branch on GitHub
2. Azure detects the change and triggers continuous deployment
3. Azure pulls the latest code
4. Azure runs `npm install` to install dependencies
5. Azure starts the application with `npm start`
6. Health check confirms the app is running
7. Traffic is routed to the new instance

### 5.4 Startup Configuration

Package.json start script:

```
"start": "node server.js"
```

Azure automatically detects the entry point and starts the Node.js process on the port provided via the `PORT` environment variable.

### 5.5 CORS Configuration

The backend explicitly allows requests from the Azure Static Web Apps frontend origin:

```
app.use(cors({
  origin: process.env.FRONTEND_URL,
  credentials: true
}));
```

## 6. Database Deployment (MongoDB Atlas)

### 6.1 Cluster Details

- Provider: AWS
- Region: Singapore (ap-southeast-1)
- Cluster tier: M0 Sandbox (Free)
- Storage: 512 MB (283 MB currently used)
- Connection type: SRV auto-discovery

### 6.2 Replica Set Configuration

The M0 tier automatically provisions a three-node replica set:

- 1 Primary node — handles all writes
- 2 Secondary nodes — replicate data from primary
- Automatic failover election in approximately 10 seconds
- No manual configuration required

### 6.3 Network Access

Atlas Network Access whitelist configuration:

- Development: Whitelist local machine IPs
- Production: Allow access from anywhere (0.0.0.0/0) since Azure IPs are dynamic
- Alternative for production: Use Azure VNet peering if on paid tiers

### 6.4 Database User

A dedicated database user with `readWrite` role on the DSIMS database is created in Atlas. Credentials are used in the `MONGO_URI` environment variable.

### 6.5 Connection String Format

```
mongodb+srv://<username>:<password>@<cluster>.mongodb.net/<database>?retryWrites=true&w=majority
```

The SRV format auto-discovers all replica set members and handles failover transparently.

## 7. Deployment Checklist

### Before Deploying

- All environment variables identified and documented
- MongoDB Atlas cluster created and accessible
- GitHub repository connected to Azure services
- CORS origin configured to match frontend URL
- JWT secret is a strong random string (not default)

### After Deploying

- Verify health check endpoint returns 200
- Test login flow end-to-end
- Test issue creation from frontend to database
- Verify email verification links use correct BACKEND_URL
- Check Azure logs for any startup errors
- Verify CORS is not blocking frontend requests
- Test all four role dashboards

## 11. Rollback Strategy

If a deployment introduces issues:

### Frontend Rollback
- Revert the offending commit in GitHub
- Push the revert commit
- Azure automatically rebuilds and deploys the previous version

### Backend Rollback
- Same process: revert in GitHub, auto-deploys
- Alternative: Azure Portal → App Service → Deployment Slots (paid tiers)

### Database Rollback
- MongoDB Atlas offers point-in-time backups (paid tiers)
- Manual backups can be exported using `mongodump`
- For M0 free tier, maintain application-level backup exports

## 12. Security in Production

- All traffic uses HTTPS (enforced by Azure)
- Environment variables never committed to Git
- JWT secret is a long random string
- MongoDB credentials use strong passwords
- Rate limiting protects against brute force
- CORS restricts API access to authorized origin
- Helmet.js adds 11 security headers
- Regular dependency updates to patch vulnerabilities

## 13. Troubleshooting

### Common Issues

| Issue | Cause | Solution |
|-------|-------|----------|
| CORS error | Frontend URL not in backend CORS config | Update `FRONTEND_URL` env var |
| 500 on startup | Missing environment variable | Check Azure Configuration settings |
| MongoDB connection timeout | IP not whitelisted in Atlas | Add IP or use 0.0.0.0/0 |
| Email verification link broken | `BACKEND_URL` uses localhost | Set env var to production URL |
| Cold start delay | Free tier idles after inactivity | Upgrade to paid tier or use warm-up ping |
| 401 on all requests | JWT secret changed after deployment | Users must re-login |
